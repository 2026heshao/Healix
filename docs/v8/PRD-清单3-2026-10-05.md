## 五、逐项需求

### R1｜文本型自定义目标（对应清单3 1-1，需求变更）

**优先级：P1**

**现状（已核实）**
- 「添加目标」弹层只渲染宿主传入的固定槽位（`AddGoalSheet.kt:61-70`），可选集合 = `GoalSlots.ADDABLE`（`GoalEntities.kt:147`）；结构上限 = 主目标 1 + 次目标 5 = 6（`GoalEntities.kt:144-146` KDoc）。
- 主目标自由文本先例：`SettingsKeys.GOAL_STATEMENT`（`SettingsKeys.kt:179`），输入上限 80 字（`SettingsFragment.kt:939 GOAL_STATEMENT_MAX`），空白输入不落库（`SettingsFragment.kt:526`）。
- **关键发现（决定存储选型）**：`GOAL_STATEMENT` 已被 AI 口径消费——`PlanGenerator.kt:380`（进计划 prompt）、`TrainingPlanner.kt:502-507`（进训练 prompt）。因此自定义**次目标**必须落**独立新键**，复用「自由文本进 settings」的存储**模式**但复用键本身会把自定义文本带进 AI 计划口径，违反本轮边界。

**已拍板**（2026-10-05 21:46，Q1）：先做文本型（零 schema 变更）；计入 6 项结构上限（主目标 1 + 次目标 5）；数值型自定义目标列二期。

**目标交互（动作序列）**
1. 用户点设置页目标组「添加目标」→ 弹层列出可添加槽位（固定槽位 + 「自定义目标」入口行）。
2. 用户点「自定义目标」→ 弹 FieldSheet 单行文本输入（1–80 字，沿用 `GOAL_STATEMENT_MAX` 先例；空白输入不落库）→ 保存后目标组出现自定义行。
3. 用户左滑自定义行 → 清空对应 settings 键（文本型无归档态）→ 弹撤销条（复用 `UndoBar`）。
4. 上限语义：自定义目标占用 1 个次目标槽位；配合 R3 把 kcal 移出 `ADDABLE`（`GoalEntities.kt:147`）后，`ADDABLE` = 体重 / 每周训练 / 睡眠 / 饮水 4 个固定槽位 + 自定义 1 个槽位，满员 6 项时入口置灰逻辑不变（`AddGoalSheet.kt:55-58` 兜底空态沿用）。

**技术要点（推荐方案，供架构师确认）**
- 新增 settings 键 `custom_goal_text`（在 `SettingsKeys.kt` 登记，进 CI `check_settings_keys`）；占位判据 = 键值非空。单键即满足 6 项上限（二期数值型如需多槽再评估键名扩展）。
- **导出侧纪律**：`custom_goal_text` 为非敏感自由文本，允许随 `ExportWriter` 整表带出（`ExportWriter.kt:186-191` 行为不变）；导入侧随 settings 常规路径恢复。
- **下游渲染边界（本轮明确）**：自定义文本型目标**只做展示**——设置页目标组渲染、个人信息页只读展示、首页三卡在读取时按无该行兜底。`MainViewModel` / `PlanGenerator` / `TrainingPlanner` 的 AI 计划口径**读取路径零变更**（键分离天然保证：它们只读 `GOAL_STATEMENT` / `goals` 表，自定义键在其读取集合之外）。`ChatEngine.systemPrompt` 字节冻结不触碰。

**验收标准（checklist）**
- [ ] 「添加目标」弹层出现「自定义目标」入口；输入 1–80 字保存后，设置页目标组出现自定义行。
- [ ] 自定义行可左滑清除，撤销后恢复。
- [ ] 4 个固定槽位 + 自定义全部启用时（合计 6 项）入口置灰；清掉任一槽位后恢复可选。
- [ ] 全程零 schema 变更（Room version 不动、无新 Migration）。
- [ ] `custom_goal_text` 在 `SettingsKeys.kt` 登记，CI `check_settings_keys` / `check_duplicate_constants` 通过。
- [ ] 导出 JSON 中 `custom_goal_text` 随 settings 正常带出，导入后恢复。
- [ ] AI 计划/训练 prompt 内容与改动前逐字节一致（`PROMPT_VER` 不递增）。

### R3｜设置「热量摄入」独立栏（对应清单3 1-3，方案 A）

**优先级：P1**

**现状（三处交叉，已核实）**
1. kcal 数值目标住 `goals` 表 `kcal_daily` 行（`GoalEntities.kt:76 KCAL_DAILY`；`GoalSlots.KCAL` `GoalEntities.kt:127`）；旧 `TARGET_KCAL` 已迁移（`SettingsKeys.kt:198-204`）。
2. 记录页热量行显隐消费 `HIDE_KCAL`（`RecordFragment.kt:445-453`，`fragment_record.xml:274` 单行）；PRD §14.3 隐私口径：隐藏时系统提示词也去数字（`ChatEngine.kt:237,267` 现有逻辑）。
3. 隐私组 UI 入口已整体移除（`SettingsFragment.kt:122`）→ 当前没有任何 UI 能控制热量行显隐，本项补位。
4. kcal 数值编辑已有现成逻辑：`SettingsFragment.editGoalKcal()`（`:598-611`），值域 `KCAL_MIN..KCAL_MAX` = 100..9999（`:978-979`），越界输入忽略。

**已拍板**（2026-10-05 21:46，Q2/Q3）：
- **Q2 开关语义** = 「记录页是否显示热量盈余行」（= `HIDE_KCAL` 取反），与 §14.3 一致；AI 计划口径随显示状态联动（隐藏时提示词去数字），开关本身只控显示语义。
- **Q3 数据归属 = 方案 A**：新栏是 kcal 的唯一 UI 入口（开关 + 数值行）；kcal 从 `GoalSlots.ADDABLE` 移除、目标组 UI 收编；已创建的用户数据行保留，仅 UI 收编。

**目标交互（动作序列）**
1. 用户进设置页 → 「目标」组之后出现独立分组「热量摄入」= 分组标题 + 开关行 + 数值行。

3. 数值行：点行弹 FieldSheet 数字输入（100–9999 kcal，沿用 `KCAL_MIN/MAX`），读写 `goals` 表 `kcal_daily` 行（复用 `editGoalKcal` 逻辑迁移到新栏）。

5. 老用户升级后：已创建的 `kcal_daily` 数据行原样保留并继续驱动首页汇总/预警/计划口径；老用户的 `HIDE_KCAL` 取值原样生效，开关初始态如实反映。

**技术要点**
- 引入 `SwitchMaterial`：全项目布局当前无任何 Switch 先例（已核实），需在「热量摄入」分组布局首次使用；样式遵守设计规范 v3（无渐变、accent 强调色）。

- `GoalSlots.ADDABLE` 收窄后，R1 的自定义槽位恰好补足「次目标 5」结构（见 R1 第 4 条动作）。

### R4｜帧率探针（对应清单3 2-1，诊断工具）

**优先级：P1**

**定位**：面向开发的**诊断工具**，非用户功能——不上设置页、无用户可见业务入口、不进任何用户旅程文档。

**背景**：二级页退出卡顿（未做3 2-1）症状为「前半段流畅、中间卡一下、后半段流畅」的单帧长任务指纹；`b0a351b` 已消除 replace 重建但真机复测仍卡；真机无 logcat，需落盘采集把「中间那一下」与同刻主线程任务对齐。

**采集内容**
1. Choreographer 帧时间戳：`Choreographer.postFrameCallback` 记录相邻帧间隔，超过阈值（推荐 2×vsync ≈ 32ms @60Hz）记一条「长帧」。
2. Looper 主线程消息耗时：`Looper.getMainLooper()` 外包 `Printer`（或 MessageQueue 监听），记录 dispatch 起止，超过阈值（推荐 ≥ 16ms）记「msg target + what + 耗时」。

**落盘与读出**
- 落盘：`filesDir` 下滚动日志文件（如 `perf_probe_YYYYMMDD.log`，单文件上限滚动覆写，推荐 2MB）；行格式含时间戳，可与卡顿时刻对齐。
- 读出：`DebugActivity` 增加「导出探针日志」入口（share intent / 复制到导出目录），用户复现一程后回传文件。

**开关策略（明确推荐：默认关闭，DebugActivity 内手动开关）**
- **推荐理由**：① 探针自身有主线程开销（观察者效应），常驻会污染被测量的卡顿本身；② 常驻写盘引入存储与隐私负担；③ 排查是低频事件，用户在复现会话中开一次即可。默认关闭的成本是「每次排查需手动开」，远小于常驻的测量失真。

**验收标准（checklist）**
- [ ] DebugActivity 内有探针开关，默认关闭；关闭状态全项目零采集、零写盘。
- [ ] 开启后二级页进出一次，日志文件生成且包含：长帧记录行 + 同刻主线程消息耗时行，时间戳可对齐。
- [ ] 「导出探针日志」可把文件分享出去。
- [ ] 开关状态重启保持；日志文件大小受滚动上限约束。
- [ ] 探针代码路径与业务代码零耦合（独立类，业务文件仅 DebugActivity 触碰）。
