## 一、本轮真机反馈（4 项）

### 1-1 「添加目标」需支持自定义目标（需求变更）

- **用户反馈**：期望添加目标支持自定义，实际弹窗仍是固定几项让用户选。
- **代码现状**：`AddGoalSheet` 只渲染宿主传入的固定槽位（`AddGoalSheet.kt:61-70`）；可选集合 = `GoalSlots.ADDABLE`（5 个固定槽位：热量/体重/每周训练/睡眠/饮水，`GoalEntities.kt:141`），结构上限 = 主目标 1 + 次目标 5 = 6 项（`GoalEntities.kt:137-141` KDoc 明示「无自由新增路径」）。
- **设计出处**：`PRD-增量.md:200` 当时明确推荐「仅恢复已归档目标 + 补齐固定指标集，**不引入用户自定义指标**」——现状是按 PRD 实现的；本轮按用户新要求翻案，**属需求变更**，PRD 对应处需同轮改齐（含 Open Questions 汇总段的同一事实表述）。
- **改动面**：
  1. 数据层：`goals.metric` 是固定枚举（`GoalMetrics`，`GoalEntities.kt:70`）——自定义目标需新 metric 约定（如 `custom:<id>`）或新表；注意 `GoalDefaults` 兜底纪律与导出/导入字段清单（备份链路要带上新字段）。
  2. 弹层：`AddGoalSheet` 增加「自定义目标」入口 → 输入名称 +（数值型时）目标值。
  3. 下游渲染：`MainViewModel` / `PlanGenerator` / `TrainingPlanner` / 首页三卡对自定义 metric 的展示与计算兜底（自定义目标大概率不进 AI 计划口径，需明确）。
- **推荐路径**：第一步先支持**文本型自定义目标**（沿用主目标自定义态先例 `GOAL_STATEMENT`，低风险、零 schema 变更——自由文本进 settings）；数值型自定义目标作为第二步单独评估。
- **【拍板点】**：① 自定义目标形态：仅文本型，还是数值型（名称+目标值+进度）？② 是否计入 6 项上限？

### 1-2 弹层下拖时白色背景不动（Bug，可直接修）

- **现象**：弹层拉到下方，把手/标题/内容移动，白色背景停留原地（真机截图实证）。
- **根因（已定位）**：`GrabberLayout.onTouchEvent` 把拖拽位移设在**自身**（`GrabberLayout.kt:72` `translationY = dy`），而 Material `BottomSheetDialog` 的外层容器（`design_bottom_sheet`）自带**不透明白底**（默认 `colorSurface`，项目未自定义 bottomSheetStyle 覆盖，`themes.xml` 无 BottomSheet 条目）——卡片被拖走后露出的是容器的白底，视觉上「白底没动」；变暗遮罩也保持原位。
- **影响面**：所有用 GrabberLayout 的弹层共 7 处（AddGoalSheet / ActionConfirmSheet / EventEditSheet / FieldSheet / GoalDetailSheet / GoalSetupSheet）——一处修全局生效。
- **推荐修法**：弹层容器透明化——统一给 `BottomSheetDialog` 主题加 `bottomSheetStyle`（背景透明），只留各弹层自己的 `bg_sheet` 圆角卡片随拖移动；修完验证：下拖跟随、松手弹回、圆角无白边、点遮罩关闭。
- **风险**：低（纯视觉层，无逻辑改动），无需拍板，可并入下一轮代码批次。

### 1-3 设置新增「热量摄入」独立栏（开关 + 数值配置）

- **用户需求**：设置中单独起一栏「热量摄入」：一个开关（Material 开关样式）+ 热量数值配置项；开启后，记录页「今日盈余」行显示热量（`fragment_record.xml:274` 单行），数值由用户自行配置。
- **代码现状（三处交叉，先定数据源归属再动手）**：
  1. kcal 数值目标现住「目标组」kcal 槽位（`GoalSlots.KCAL`，`GoalEntities.kt:127`；旧 `TARGET_KCAL` 已迁移进 goals 表，`SettingsKeys.kt:198-204`）；
  2. 记录页热量行显隐消费方读 `HIDE_KCAL`（`RecordFragment.kt:445`，PRD §14.3 隐私口径：隐藏时系统提示词也去数字）；
  3. v8 需求 6 已把「隐私」组 UI 入口整体移除（`SettingsFragment.kt:122`）——**当前没有任何 UI 能控制热量行显隐**，本轮需求正好补位。
- **方案选项**：
  - **A（推荐）**：新栏做 kcal 的唯一 UI 家——设置页新增「热量摄入」分组 = 开关（接 `HIDE_KCAL` 取反语义）+ 数值行（读写 goals kcal 行）；同时把 `KCAL` 从 `GoalSlots.ADDABLE` 移除、目标组不再显示 kcal 行（已创建的用户数据行不动，仅 UI 收编）。符合「一个事实一个入口」纪律。
  - B：新栏只做现有两处的 UI 投影，目标组 kcal 槽位保留——设置页出现两处热量入口，冗余，不建议。
- **控件**：项目内暂无 Switch 先例（全布局无 Switch/SwitchCompat），需引入 `SwitchMaterial`（material 库已在依赖中，`BottomSheetDialogFragment` 已在用）。
- **【拍板点】**：开关语义 = 「记录页是否显示热量盈余行」（推荐，与 §14.3 一致、改动面小），还是「是否启用热量功能」（关闭时连带 AI 提示词/计划口径一起关，改动面大）？

### 1-4 个人信息页目标行 → 只读 + 跳转（已实现，待发布验收）

- **用户需求**：个人信息里的目标变为设置里主目标的只读展示 + 点击跳转到设置的目标配置栏。

- **待办**：随并行批次入库发布后真机验收一条：个人信息 → 点目标行 → 落在设置页目标配置栏位置。
