## 一、设计原则：丝滑感的四个来源

1. **反馈即时**：一切触点在 150ms 内有视觉响应（焦点线、发送键变色、按压态）。超过 200ms 的反馈用户感知为「迟钝」。
2. **状态连贯**：状态之间切换全部走动画，禁止「有/无」跳变（如顶线从无到有、发送键从灰到橙直接换帧）。
3. **键盘协同**：输入条永远贴住键盘顶、焦点行永远滚进可视区、IME 动作键（发送/下一项/完成）与屏上按钮行为一致。
4. **失败可恢复**：输入内容是用户资产。发送失败文本**原样回填**、光标落尾部；任何清空动作前内容已在本地持久化。

## 二、焦点反馈（唯一新增装饰：1dp 焦点线）

现状：所有输入框焦点态只有光标变色（accent，`themes.xml:31-32`），键盘弹出是唯一大反馈——对 Sheet 字段行、设置行内输入这类「无键盘动作」的场景反馈偏弱。

**方案**：为类型 2/3/4（行内与块状输入）增加 **1dp 焦点底线**，颜色 `line → accent` 过渡 150ms（`--ease-standard`）。与常驻输入条的 1dp 顶线（`bg_input_bar.xml`）是同一视觉语言，不破坏 v3。

| 属性 | 规格 |
|------|------|
| 线宽 / 位置 | 1dp，行底部（Sheet 字段行、设置行）；块状多行放**顶部**（与其余输入条顶线语言一致） |
| 颜色 | rest `line`(#EAE8E4) → focus `accent`(#B85028)；焦点离开过渡回 `line` |
| 时长 / 曲线 | 150ms，`cubic-bezier(0.2, 0, 0, 1)` |
| 实现 | color selector（`res/color/focus_line.xml`）驱动 layer-list stroke 色，EditText `background` 引用；**零代码** |
| 类型 1（常驻输入条） | 已有顶线即视觉锚，焦点反馈保持「光标 + 键盘」，不重复加线 |

**推荐结论**：焦点线做在类型 2/3/4，一处 drawable + selector 覆盖全部行内输入；常驻输入条不动。

## 三、状态机（按类型 1 展开；其余类型为其子集）

```
rest ──(获得焦点)──▶ focused ──(文本非空)──▶ filled ──(点击发送)──▶ sending ──┬─(成功)──▶ sent
  ▲                        │                                                │
  └──────(失焦且空)─────────┴────────(文本被清空，回到 focused)──────────────┴─(失败)──▶ failed
                                                                        （failed：文本回填，光标尾部，1 次轻触觉）
```

### 各状态规格（类型 1 · 常驻输入条）

| 状态 | 视觉 | 行为 | 现状差异 |
|------|------|------|----------|
| rest | 顶线 `line`，hint text_2 | 输入条常驻可见 | 已达成 |
| focused | 光标 accent | 键盘弹出，TabBar 隐藏（`TabBar.kt:104-112` 已实现） | 已达成 |
| filled | 顶线不变；**发送图标 `text_3 → accent` 150ms 过渡** | 发送键可点 | 【新增】见第四节 4.2 |
| sending | ProgressBar 20dp accent 旋转 + 13sp 灰字「识别中/排队中」 | 输入框**保持可编辑**（打字不丢），发送键防重入 | 现状已有 spinner 与 stateLabel（`activity_chat.xml:197-215`）；「输入框保持可编辑」为新增约束 |
| failed | stateLabel 显示 13sp `negative` 文字（如「发送失败，已保留原文」） | 文本原样回填输入框，`setSelection(length())`，1 次轻触觉 | 【新增】失败回填，现状未核实到恢复路径【待核实】 |
| sent | 输入框清空 | 光标留在输入框，焦点不释放（连续输入免二次聚焦） | 【新增】焦点保持策略 |

### 类型 2/3（行内输入）状态子集

- rest → focused（焦点线 150ms）→ filled → **失焦即保存**（现状 `ResourceFragment.kt:72` 已是失焦保存，扩展为全行内输入统一口径）。
- 保存成功**无任何提示**（克制：不打扰是最高反馈）；保存失败走页面级 toast，13sp text_1。

### 类型 4（块状多行）状态子集

- 与类型 3 同，另加：内容为空且失焦时恢复 hint（`text_3`），有内容则永久显示正文——避免「已填内容突然消失」的错觉。

## 四、微交互规格（时长 / 曲线 / 触觉，全 App 统一 token）

### 4.1 动效 token（建议收进 `dimens.xml` / styles 注释）

| token | 值 | 用途 |
|-------|----|------|
| `motion_fast` | 100ms | 发送键变色、按压态 |
| `motion_focus` | 150ms | 焦点线过渡 |
| `motion_grow` | 200ms | 输入条高度自适应 |
| 曲线 | `cubic-bezier(0.2, 0, 0, 1)` | 全部过渡统一用 Material 标准曲线 |

### 4.2 发送键双态（P0，成熟输入框的分水岭）

- 空文本：图标 `text_3`(#9C9891)，可点但点击后仅触发焦点（用户预期一致）。
- 非空：图标 `accent`(#B85028)，100ms 过渡。
- 实现：`TextView`/`ImageButton` 用 color selector `res/color/btn_send_tint.xml` 绑定文本长度状态（一个 `TextWatcher` 里 `drawable.setState()`），零动画代码。
- 位置：`fragment_assistant.xml:225-232` btnSend、`fragment_record.xml:580-589` 同构发送键。现状 tint 色**已核实：`ic_send.xml:10,17` 把 strokeColor 硬编码成 `@color/accent`，`res/color/` 目录不存在 → 无任何 selector，图标恒为 accent**（原稿标【待核实】，现已坐实缺失）。

### 4.3 输入条高度自适应（P0 候选）

- 现状：输入条固定 `input_height` 64dp（`dimens.xml:18`），QuickInput `maxLines=3`（`themes.xml:107`）。15sp × 默认行高 ≈ 23dp/行，3 行 ≈ 69dp **大于** 64dp 容器，第三行疑似被裁。【待核实：真机连打三行确认是否裁切】
- 方案：输入条改 `wrap_content` + `minHeight 64dp`，高度随行数 1→3 行以 200ms `motion_grow` 平滑增高（`ValueAnimator` 挂 `EditText` 行数变化）；输入条增高时聊天列表同步 `smoothScrollToPosition` 底部。
- 记录页与聊天页共用此行为（两处 `bg_input_bar` 同构）。

### 4.4 触觉（P2，克制使用）

- 仅两处：发送点击（`HapticFeedbackConstants.VIRTUAL_KEY`）、失败回填（同常量，轻、单次）。
- 系统关闭触觉时自动失效，无需开关。全 App 其他输入动作不加触觉。

### 4.5 按压态（已有，保留）

- 发送键 `selectableItemBackgroundBorderless`（`activity_chat.xml:221`），热区 48dp（`touch_min`）。规格达标，维持。

### 修正 3 · P0-3「失败回填」的前提不成立（本项目是 persist-first）
- 原稿假设「失败 = 输入被清空、文本丢失」。实际：记录链 `EventRepository.submit` 第一步就 `insertIgnore` 原文（`MainViewModel.kt:558-560` 注释明写「原文一定入库」）；聊天链**先** `persist("user", text)` 再调模型（`ChatViewModel.kt:182-183`）。
- **无条件回填 → 用户再点发送 → 落重复 user 行 / 重复 pending 行。**
- 改为「**只在文本真的没被接受时回填**」：`ChatViewModel.send(text)` 返回 `Boolean`（唯一在 persist 之前 return 的守卫是跨零点守卫 `ChatViewModel.kt:175`），返回 `false` 才保留原文 + `stateLabel` 一行 13sp `negative` + 1 次轻触觉。记录页不存在丢文本路径，**不回填**，只补「清空后焦点保持」与触觉。

### 修正 5 · ★ 既有缺陷：`bg_input_bar.xml` 的线画在错误的那条边上
- 语义（两个独立来源证实）：`<item>` 的**负向 inset = 移除该边**。StackOverflow 高票答案原文「give a negative value for the side border you want to **remove**」；中文实测博客「把 top、right、left 设置成 -2dp，而 shape stroke 的宽度只有 1dp，这样**上右左边线都没了，只有底边会保留**」。
- 原 `bg_input_bar.xml` 第二层 = `top/left/right = -1dp` → 实际渲染的是**底边线**；而 `docs/Healix设计规范系统.md:174` 要求「速记框…顶部 1dp **上边界线**」，原稿 §二 也称其为「顶线」。**即记录页/对话页输入条的分隔线一直画在错误的那条边上。**
- 同一博客另点出：**-1dp 推不净**（1dp stroke 会在描边外侧多留约 1dp margin），需 **-2dp** 才能完全去除被推的边。
- 处置（用户拍板「修掉，对齐规范」）：`bg_input_bar.xml` 第二层改为 `bottom/left/right = -2dp`（保留顶边）；本次新增的两个 drawable 同样用 **-2dp** 而非 -1dp。

### 修正 6 · 检查器盲区（已同轮修复 + 坏例自证）
`pipeline/check_resources.py` 的 `declared["color"]` 只扫 `values*/`，**不扫 `res/color/`** → 新布局写 `android:tint="@color/btn_send_tint"` 会被误报「引用不存在的 @color」。
→ 已把 `res/color/*.xml` 的 stem 并入 `declared["color"]`，并**注入坏例自证**（把引用改成不存在的名字 → 报错 1 项；改回 → 0 报错），证明修复真实生效、不是静默跳过。
