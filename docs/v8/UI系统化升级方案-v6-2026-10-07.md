# Healix UI 系统化升级方案（v6 大幅升级版）

日期：2026-10-07 ｜ 方向：**大幅升级**（经主理人拍板：引入卡片容器、阴影层级、辅助色系）
配套高仿真画板：`docs/prototypes/UI-升级方案高仿真-v6.html`（全局画板：三 Tab + 二级页 + 弹层 + 深浅双模式）
现行规范：`docs/Healix设计规范系统.md`（v5）—— 本方案升版为 **v6**，冲突处按本文裁决。

---

## 一、为什么升级：现状审计结论

对 v5 规范与现行实现（`res/values/colors.xml` / `themes.xml` / `type.xml` / `dimens.xml`）审计后，"极简禁欲"语言的优势是克制、耐看，但随功能膨胀已暴露四个系统性瓶颈：

| # | 问题 | 表现 | 影响 |
|---|------|------|------|
| 1 | **层级只能靠灰度** | 全部内容平铺在同一白色平面上，无容器分组 | 首页 381dp 固定顶区内信息黏连，扫视成本高（9.1 预算余量仅 9dp 的根源之一） |
| 2 | **字重档位过窄** | 仅 400/500，标题与正文拉不开对比 | "标题感"靠 17sp 硬撑，大数字与正文的戏剧张力弱 |
| 3 | **单强调色承载过载** | accent 同时承担：主按钮、进度线、链接、信号态、工具竖线、选中态 | 用户无法从颜色分辨"这是可点"还是"这是警告"还是"这是品牌" |
| 4 | **状态反馈缺乏情感层** | 达标/未达标、成功/失败仅文字色差，庆祝与安抚无视觉语言 | 健身健康类产品最需要的"正反馈循环"缺失 |

**结论（推荐）**：保留 Healix 的品牌基因（暖调中性色 + 赤陶主色），在**容器、层次、色彩广度、动效**四个维度做系统性重建，即本方案 v6。

## 二、v6 设计原则（六条，冲突时按顺序裁决）

1. **品牌基因延续**：暖白底、赤陶主色、线性 1.6dp 图标体系全部保留——用户感知是"变精致了"，而非"换了个 App"。
2. **层级 = 容器 + 灰度 + 字重 三通道**：分组靠卡片容器（surface-container 色 + 低强度阴影），强调靠 600/700 字重，辅助靠语义色。三通道各司其职。
3. **主色专注操作**：accent 只表达"可点/主操作/进行中"；达标与正向归 `success`，警示归 `warning`，错误归 `error`。情绪由语义色表达，品牌由主色表达。
4. **圆角有阶梯**：全局三级 `8 / 16 / 24`（小控件 / 卡片 / 弹层），同级恒定，杜绝混用。
5. **动效有性格**：标准曲线 `cubic-bezier(0.2,0,0,1)` 之外，引入弹性曲线 `cubic-bezier(0.34,1.56,0.64,1)` 仅用于"完成、达标"等庆祝时刻；常规交互一律标准曲线。
6. **无障碍是底线**：所有新色彩组合过 WCAG AA（正文 ≥4.5:1）；触控目标维持 ≥48dp；字体放大 200% 不破版；尊重系统"减少动画"。

### 3.1 色彩（Material 3 式 Tonal 体系，暖调）

| 令牌 | 浅色 | 深色 | 用途 |
|------|------|------|------|
| `primary` | `#B85028` | `#D4703F` | 主按钮、进行中、可点文字（= v5 `accent` 升名） |
| `on_primary` | `#FFFFFF` | `#131211` | 主按钮文字 |
| `primary_container` | `#F7E6DC` | `#4A2413` | 选中 chip 底、强调卡衬底、用户消息气泡 |
| `on_primary_container` | `#7A2F12` | `#F7D9C9` | 上述容器上的文字 |

**辅色组（从既有类型圆点色升格，零新色相）**

| 令牌 | 浅色 | 深色 | 来源 | 用途 |

| `secondary_container` | `#E2EAEE` | `#24343E` | 新推 | 信息提示衬底 |
| `tertiary` | `#6B5B7B` | `#9B8BAB` | 原 `type_body` | 体重/身体维度点缀 |

**语义组（新增 warning，正负色保留）**

| 令牌 | 浅色 | 深色 | 用途 |
|------|------|------|------|
| `success` | `#4A7C59` | `#6E9E7C` | 达标、连通成功（= v5 `positive` 升名） |
| `success_container` | `#E4EEE6` | `#1F3526` | 达标庆祝卡衬底 |
| `warning` | `#B07818` | `#D9A344` | 预警、临近超标、未识别过期 |
| `error` | `#A63D40` | `#C4565A` | 真实错误（= v5 `negative` 升名） |

**中性组（暖调延续 + 三档 surface 阶梯）**

| 令牌 | 浅色 | 深色 | 用途 |

| `text_3` | `#9C9891` | `#6E6A64` | 辅助装饰 |
| `outline` | `#DDD9D4` | `#3A3735` | 描边（= v5 `line_strong` 升名） |
| `outline_variant` | `#EAE8E4` | `#2E2C2A` | 分隔线（= v5 `line` 升名） |
| `press` | `#F2F1EE` | `#252321` | 列表按压 |

**事件类型圆点**：沿用 v5 六色（低饱和），深色统一提亮 8% 明度——这条 v5 规则原样生效。

**无障碍核验（新组合，全部 ≥ AA）**

| 组合 | 对比度 |
|------|--------|
| `text_1` / `bg` #F4F2EF | 15.4:1 ✅ |
| `text_2` / `bg` | 4.8:1 ✅ |
| `on_primary_container` #7A2F12 / `primary_container` #F7E6DC | 6.9:1 ✅ |
| `on_primary` #FFF / `primary` #B85028 | 4.98:1 ✅（沿用 v5 实测） |
| `success` / `bg` | 4.7:1 ✅ |
| `warning` #B07818 / `bg` | 4.6:1 ✅ |
| `error` / `bg` | 5.3:1 ✅ |

### 3.2 字体（新增 Display 档，字重放开到 700）

| 级别 | 字号/字重 | 行高 | 用途 |
|------|-----------|------|------|
| `display` | 32sp / 600 | 1.15 | 热量主数字（原 numeral 36sp/400 保留为"数字 hero"变体，用于首页盈余） |
| `title_large` | 22sp / 600 | 1.27 | 页面大标题（我的页头部、计划页） |
| `title` | 17sp / 600 | 1.35 | 页面标题、卡片标题 |
| `body` | 15sp / 400 | 1.6 | 正文 |
| `body_emphasis` | 15sp / 600 | 1.6 | 卡片内关键值 |
| `secondary` | 13sp / 400 | 1.54 | 摘要、时间戳 |
| `caption` | 12sp / 500 | 1.33 | 分区标题（升 500，配 letter-spacing 0.02em） |

按钮文字升为 **15sp/600**（v5 为 13sp/500，偏弱）。中文 fallback 规则沿用：细字重制造轻盈感的做法继续回避，600/700 仅用于短标签与大数字。

### 3.3 形状 / 间距 / 阴影

| 令牌 | 值 | 用途 |
|------|-----|------|
| `radius_sm` | 8dp | chip、小标签、进度线端 |
| `radius_md` | 16dp | 卡片、输入条、按钮 |
| `radius_lg` | 24dp | 底部弹层顶角 |
| `screen_margin` | 20dp（不变） | 页边距 |
| `card_padding` | 16dp | 卡片内边距 |
| `block_gap` | 24dp | 区块间距（28→24，卡片自带分组后留白可收半档） |

**阴影三级（全部极低强度，投影色取 text_1 暖黑）**

| 级别 | 值 | 用途 |
|------|-----|------|
| `elev_1` | `0 1px 2px rgba(26,25,24,.04), 0 4px 16px rgba(26,25,24,.06)` | 常态卡片 |
| `elev_2` | `0 2px 6px rgba(26,25,24,.06), 0 12px 32px rgba(26,25,24,.10)` | 悬浮操作、按压中的卡片 |
| `elev_3` | `0 -8px 32px rgba(26,25,24,.12)` | 底部弹层上投影 |

### 3.4 动效

| 令牌 | 值 | 用途 |
|------|-----|------|
| `dur_fast` | 150ms | 按压、hover |
| `dur_normal` | 240ms | 弹层、卡片状态切换 |
| `dur_slow` | 400ms | 消息进入 |
| `easing_standard` | `cubic-bezier(0.2,0,0,1)` | 常规 |
| `easing_spring` | `cubic-bezier(0.34,1.56,0.64,1)` | **仅**庆祝时刻（达标打勾、进度完成） |

微交互规格：卡片按压 = scale 0.98 + 阴影升一级（120ms）；chip 选中 = 底色切换 150ms；Tab 切换维持 v8 拍板的**零动画**（点 Tab 即响应，本文原样继承）；页面转场维持"整屏 translate"规格（见 MEMORY §7，`e968072` 的约束不因 v6 改变）。

## 五、操作交互系统化升级

### 5.1 手势与操作总表

| 操作 | 位置 | 行为（点哪里 → 到哪里） |
|------|------|--------------------------|
| 点 Tab（记录/助理/我的） | 底部导航 | 零动画直切（v8 拍板继承）；再次点当前 Tab → 列表滚回顶部 |
| 下拉记录列表 | 记录页 | 刷新聚合数据（本地 0 次 AI）；刷新指示器 = primary 细环 |
| 左滑记录行 | 记录页 | 滑出 72dp 删除块（`error` 底白字圆角块），松手删除 + 底部撤销条 5s（沿用现 SwipeController 阈值） |
| 点记录行 | 记录页 | 进编辑弹层（v6 顶角升级，逻辑不变） |
| 发送速记 | 记录页/助理页 | 直接落库 → 行内"识别中" → 原地回填（PRD 十五章路径**原样保留**） |
| 长按对话消息 | 助理页 | 弹出复制 / 引用菜单 |
| 点指标 chip | 记录页 | ~~进状态详情页（分段 Tab 规格 9.4 不变）~~ **实现裁决：改为开 GoalDetailSheet**（见 §九-2） |
| 点 Hero 卡达标环 | 记录页 | ~~进今日计划页计划 Tab~~ **实现裁决：改为开 GoalDetailSheet（盈余视角）**（见 §九-2） |

### 5.2 转场与加载

- 页面转场：整屏 translate 320ms `easing_standard`，被覆盖层 22% 视差（v8 已修规格照抄，**禁 alpha 叠影**）。
- 卡片级骨架屏：列表首载 300ms 内未出数据时显示 3 张 `surface_variant` 占位卡（呼吸 1.2s）。
- 弹层：底部滑入 240ms + scrim 32% 黑（沿用 v5 淡遮罩）。
- Reduced motion：系统减少动画开启时全部位移归零，只留 100ms 透明度。

### 5.3 空态与庆祝态（v6 新增情感层）

| 场景 | 表现 |
|------|------|
| 首日空态 | Hero 卡显示目标引导 + 一句示例；记录区 `surface` 卡内居中 13sp `text_2` |
| 三链全无数据 | 指标区显示"建立第一条记录后点亮"占位 chip |
| 当日达标 | Hero 卡达标环走满 + 一次 400ms `easing_spring` 缩放；`success_container` 淡衬底维持到次日 |
| 连续达标 7 天 | ~~我的页"连续达标"徽章从 outline 描边升级为 `success_container` 实底~~ **实现裁决：徽章整体移除**（与 PRD 硬规则 R5 冲突，见 §九-1） |

## 八、与 v5 的冲突裁决表

| v5 原则 | v6 裁决 |
|---------|---------|
| 原则 1"层级只由字号字重灰度决定" | 升级为三通道（容器+灰度+字重），本方案 §二-2 |
| 原则 2"无容器、无阴影" | 废止；代之以三级阴影与卡片体系 |
| 原则 3"圆角唯一 8dp" | 废止；代之以 8/16/24 三级阶梯 |
| 原则 4"透明的过程" | **原样保留**（AI 行为可见性是产品价值观，非视觉问题） |
| 原则 5"对话不用彩色气泡" | 废止；代之以语义化气泡（§四对话消息行） |
| §2.1"accent 外不用高饱和色" | 收窄语义：语义色仅出现在文字与容器衬底，事件圆点体系不变 |
| §六"UI 图标 8 个封顶" | 放开：底部导航 3 枚 Tab 图标 + 达标环，共新增 ≤5 枚线性图标（1.6dp 描边体系不变） |

## 九、实现裁决记录（2026-10-07 落地，P0+P1+P2）

> 本节记录**实现与本文原设计的偏离及理由**。本文其余条款为设计意图，未列入本节者均按原文落地。

### 九-1 「连续达标 7 天徽章」整体移除（§5.3）
- **冲突**：`PRD` 硬规则 `R5` + 规范 §9.12 禁止「可累积 / 会归零 / 给奖励 / 能排行」的 streak 机制，并配置了静态守卫 `pipeline/check_kotlin.py` 的 `check_no_gamification`（明确允许「连续 3 天睡不到 6 小时」这类**描述数据**的文案）。
- **工程事实**：全仓不存在「连续达标」聚合口径（grep 无 streak / 连续天数 / 达标天数实现）。
- **裁决**：**移除**。落一个无数据源的 `visibility=gone` 视图等于死代码，且长期与 R5 打擦边球。
- **落点**：`fragment_mine.xml` 个人卡移除徽章子树；`drawable/bg_streak.xml`、`dimen/streak_pad_h`、`string/dui_consecutive_label` 同步删除（零残留引用）。
- **后续若做同类正反馈**：改用**描述性**口径（如「本周达标 5/7 天」），R5 明确允许描述数据的文案。

### 九-2 指标 chip / Hero 卡达标环 → 保留 v8 `GoalDetailSheet`（§5.1）
- **原设计**：指标 chip → 状态详情页；Hero 卡达标环 → 今日计划页。
- **工程事实**：v8 现状是两者都开 `GoalDetailSheet`（半屏弹层，含 训练/睡眠/体重 三分段 + 180dp 大折线）。
- **裁决**：**保留 v8 去向**。理由：① `GoalDetailSheet` 功能更丰富，改跳转会让其 `metricContent` 成死代码（功能架空）；② v6 定位是**视觉层升级**，不应改变既有功能归属。
- 信号态 chip 仍进 `StatusDetailFragment`（身体段）+ `acknowledgeSignals`，与原逻辑一致。
