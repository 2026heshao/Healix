# Healix v8 调研：竞品功能借鉴

> 作者：产品经理 许清楚
> 日期：2026-10-05
> 目的：在 `docs/参考产品研究与取舍.md`（2026-10-03 旧版）基础上更新，为 Healix v8「UI/交互成熟化」选取**最实用且契合本应用**的功能做二次改造落地。
> Healix 前提约束（决定"契合"与否）：**本地优先、零成本（免费档 LLM）、极低摩擦记录、无卡片/无阴影/无渐变/唯一强调色、无多用户/无社交/无付费/无云同步。**

## 〇、结论先行

**推荐落地 3 个功能（P1）+ 1 个顺带做（P1，零额外成本）+ 1 个备选（P2）：**

| 排名 | 借鉴功能 | 来源 | 为什么契合 Healix | 成本 | 优先级 |
|---|---|---|---|---|---|
| 1 | **恢复度驱动训练**：时间轴上标"上次练距今 + 该肌群恢复度"，避开未恢复肌群 | Fitbod / Hevy | Healix 已有 `MuscleRecovery` + `completedDows`，**纯本地、0 AI** | 小-中 | P1 |
| 2 | **"上次值"记忆回显**：记录弹窗按同类型/同动作回显上次数值 | Hevy / MyFitnessPal | 直接服务"打开即记"，减少输入 | 小 | P1 |
| 3 | **就医准备材料**：一键把时间窗内事实整理成一页可读摘要 | Bearable | 旧研究 R1 已论证，最高用户价值，天然不越医疗边界 | 中 | P1 |
| 4 | **趋势优先 / 只显示关注指标**：不做单日报警，只展示周/月方向 | Apple Health | 与 PRD 需求 5 的次目标图表同源，顺带实现 | 小 | P1 |
| 5 | **最近常吃 / 多记录方式复用**：一键复用最近记录与常吃池 | MyFitnessPal / 薄荷健康 | Healix 已有 `presets` + `FoodPool`，扩展即可 | 小 | P2 |

**明确的否决（继续保持不做）**：综合健康评分、恢复评分、streak/连续打卡/归零/勋章、社交/排行、云同步、传感器采集（步数/睡眠分期/心率/轨迹）、跟练课程。理由见旧研究 `参考产品研究与取舍.md` 第 2.4 / 第四章。

## 三、可借鉴点 → Healix 二次改造落地方案

### 功能 1｜恢复度驱动训练 ★首选

- **借鉴点**（Fitbod / Hevy）：Fitbod 按"已记录的训练"给每个肌群算恢复度，48–72 小时内不重复高强度；Hevy 用组数×次数×重量做渐进超负荷统计。**都不需要传感器**。
- **Healix 现状（已核实）**：`rules/MuscleRecovery.kt` 已能按 `events(type=exercise)` 算肌群与恢复度；`TrainingPlanner.completedDows()`（`ui/TrainingPlanner.kt:475-489`）已有"本周哪天已练"判定；训练 prompt（`TrainingPlanner.kt:71-90`）已含"同一肌群 48 小时内不重复、恢复度 <50% 本周不再安排"。
- **落地方案**：融入 PRD 需求 7 的**单条时间轴**——训练日条目右侧显示"上次练距今 N 天 · 恢复度 X%"（15sp `text_2`，无卡片），未恢复肌群在详情里给出替代建议。与"计划自动更新"共用本地重算路径。
- **数据从哪来**：`events(type=exercise)` + `MuscleRecovery`（**已有**）；无需新表/新键。
- **是否需要 AI**：**不需要**（纯本地规则；AI 仅在用户主动重排时润色）。
- **实现成本**：小-中（新增时间轴条目字段 + 本地摘要渲染）。
- **合规检查**：不得出现 `1RM` / 力量总分 / 评分（旧研究已否决；`PROMPT_TRAINING` 亦禁止输出）。仅展示可从记录核对的"距今 N 天 / 组数"等事实。

### 功能 2｜"上次值"记忆回显

- **借鉴点**（Hevy "holds the last rep and weight from the previous time"；MyFitnessPal 历史快速记录）：输入时自动带上上次同类值，减少敲字。
- **Healix 现状**：`events` 保留 `raw_text` 与结构化字段（`EventEntity.kt`）；`presets` 已是一键记录（`MainViewModel.logPreset`，`MainViewModel.kt:472-518`）；`FoodPool`（`rules/FoodPool.kt`）已有"常吃"池。记录/编辑弹窗目前不回显上次值。
- **落地方案**：确认/编辑弹窗（`sheet_confirm.xml` / `sheet_field_edit.xml`）在字段为空时，把"最近一条同 type 记录的同名字段值"作为 hint（`text_3` 灰字占位）预填，用户确认即用。**不改协议**（不新增 events 列）。
- **数据从哪来**：`events` 按 `type` + `day_key` 倒序取最近一条（**已有字段**）。
- **是否需要 AI**：**不需要**。
- **实现成本**：小。
- **注意**：预填只作为 hint，**不伪造数据**（用户不确认则不落库），符合"不制造假数据"纪律。

### 功能 3｜就医准备材料 ★高价值

- **借鉴点**（Bearable）：把"自上次就诊以来发生了什么"整理成完整记录，用户报告的核心价值（旧研究 2.2）。
- **Healix 现状**：`events`（含 `symptom`/`type=illness`/体重/睡眠/饮食/运动）+ `body_signals` 已具备全部事实；`ExportWriter` 只有原始 JSON 导出（`ui/ExportWriter.kt`），**无可读摘要**。
- **落地方案**：新增「就医材料」（入口建议放「我的」页数据组，与"导出备份"并列，不占"记录"页）。动作序列：选时间窗（近 1/3/6 个月）→ 生成一页可读摘要（症状时间线 + 体重/睡眠/饮食/运动的实际数字 + 用药/就医记录）→ 走既有 SAF `ACTION_CREATE_DOCUMENT` 保存为文本/JSON。**AI 只做整理与排版，不做任何医学判断**；未配置 provider 时走纯本地本地排版，照常可用。
- **数据从哪来**：`events` + `body_signals` + `settings`（非敏感项）——**全部已有**。
- **是否需要 AI**：**可选**（有则措辞更顺，无则本地模板；两路都必须可用）。
- **实现成本**：中（新增入口页 + 摘要渲染 + 复用 SAF）。
- **边界纪律**：不输出诊断、不输出风险百分比、不宣称因果（沿用旧研究 R6）。

### 功能 4｜趋势优先 / 只显示关注指标（顺带做）

- **借鉴点**（Apple Health）：Trends 看方向不看单日；单次异常不报警；只显示收藏的指标。
- **Healix 现状**：`TrendChartView` 已自绘折线（`ui/widget/TrendChartView.kt`）；状态行已是"两态互斥、1 条为限"（`MainViewModel.kt:195-216`）；预警规则已要求"连续 N 天"口径。
- **落地方案**：与 PRD 需求 5 的**次目标进度图表**同源落地——只展示 3 个可核对指标（本周训练次数 / 近 7 日睡眠 / 近 30 日体重），单日数据不报警、不放大数字。**零额外成本**（需求 5 反正要做）。
- **数据从哪来**：`events`（已有）。
- **是否需要 AI**：**不需要**。
- **实现成本**：小（并入需求 5）。

### 功能 5｜最近常吃 / 多记录方式复用（备选 P2）

- **借鉴点**（MyFitnessPal 历史快速记录、薄荷健康"快捷记录 + 食物库"）：常用项一键复用。
- **Healix 现状**：`presets`（横条一键记录，`activity_main.xml:57-73`）+ `FoodPool`（常吃池，`rules/FoodPool.kt`）已有；缺"最近 N 条记录一键复制"。
- **落地方案**：预设横条右侧追加"最近"项（取 `events` 最近 3 条非软删记录，点击即再次落库 + 5 秒撤销）。
- **数据从哪来**：`events` + `presets`（已有）。
- **是否需要 AI**：**不需要**。
- **实现成本**：小。
- **备注**：若要做**饮水打卡**（薄荷/Keep 有），必须先解决数据源——`events.type` 现有取值 `meal|exercise|body|sleep|illness|other` 中无"饮水"，且 `water_ml` 目前**只有目标值、无任何 event 数据**（已核实：全项目 grep `WATER_ML` 仅出现在目标与文案）。结论：**饮水打卡列 P2，且需先定数据模型（`type=other` + `amount` 或新增列，后者要动 events schema 并同步 Python 侧，不建议本期做）。**

## 四、推荐结论与优先级排序

1. **P1 恢复度驱动训练**（功能 1）——与需求 7 同轴，本地可算、0 AI、最贴合"训练"语义。
2. **P1 "上次值"记忆回显**（功能 2）——最直接服务"打开即记"，成本最小。
3. **P1 就医准备材料**（功能 3）——用户价值最高、不越医疗边界，入口放「我的」页。
4. **P1 趋势优先/只显示关注指标**（功能 4）——随需求 5 一起交付，零额外成本。
5. **P2 最近常吃复用**（功能 5）——有余力再做；饮水打卡延后并需先定数据模型。

**一句话**：Healix 的差异化不是"更多数据"，而是**"把你自己记录的事实，变成能看懂、能带走、能核对的东西"**——恢复度训练、上次值回显、就医材料，都落在这条线上，且**全部本地优先、零增量 AI 成本**。
