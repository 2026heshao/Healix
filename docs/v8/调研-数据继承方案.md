# Healix v8 调研：本地数据继承方案

> 作者：产品经理 许清楚
> 日期：2026-10-05
> 目的：为 PRD 需求 8「本地数据继承配置」给出**单一推荐方案**（结论 + 理由 + 落地成本），覆盖 schema 迁移安全网、跨设备/重装恢复、用户可操作性、隐私。
> 依据：Healix 现有实现（可指到 `文件:行号`）+ Android 官方备份机制。

---

## 〇、结论（单一推荐，不给多选题）

> **推荐：应用内 JSON 双向（导出 + 导入）+ 迁移前自动 DB 快照 + 保持 `allowBackup=false`。**

拆成三件必须一起做的事：

1. **双向**：在现有 `ExportWriter` 旁补齐 `ImportReader`，让"导出备份"从"死数据"变成"可还原的迁移包"（这是当前最大的缺口）。
2. **迁移安全网**：每次 Room 版本升级前，自动把 `healix.db`（含 `-wal`/`-shm`）复制一份快照；新增版本必须提交 schema JSON 并加迁移测试。
3. **保持隐私姿态**：`allowBackup=false` + `dataExtractionRules` 全排除**不变**；API Key 只存 `EncryptedSharedPreferences`，**绝不进任何导出/备份**。

**落地成本**：中等（导入解析 + 快照 + 迁移测试）。

**为什么不是其它方案**（逐条否决）：见第四章。

## 一、Healix 现状（已核实）

| 项 | 现状 | 文件:行号 |
|---|---|---|
| DB 版本 | version = 3，含 `MIGRATION_1_2` / `MIGRATION_2_3`，**禁 `fallbackToDestructiveMigration`** | `db/AppDatabase.kt:37,83-101,109-121,143-145` |
| schema 导出 | `exportSchema = true`；但仓库内 `app/schemas/com.healix.app.db.AppDatabase/` **只有 `1.json`、`2.json`，缺 `3.json`** | `app/schemas/...`（已 `find` 核实） |
| 导出 | 只有导出 JSON（`buildJson`），内容 = events / presets / daily_plans / daily_reviews / 非敏感 settings；走 SAF `ACTION_CREATE_DOCUMENT` | `ui/ExportWriter.kt:25-121,130-138` |
| 导入 | **不存在**（全项目 grep `OPEN_DOCUMENT`/`restore` 无业务命中） | — |
| 备份开关 | `allowBackup="false"` + `fullBackupContent="false"` + `dataExtractionRules`（cloud-backup 与 device-transfer **全 exclude**） | `AndroidManifest.xml`、`res/xml/data_extraction_rules.xml` |
| API Key | 只存 `EncryptedSharedPreferences`（AES-256-GCM，Keystore 主密钥），**不落 SQLite** | `security/SecretStore.kt:38-51,16-18` |
| 导入入口 | 导出入口在「我的」页 `rowExport` | `ui/MinePage.kt:101-106,257-264` |

**关键推论**：当前 **`allowBackup=false` + dataExtractionRules 全排除 = 换机/重装默认零恢复**；而唯一的导出又是只出不进 → 用户即便导出过，也**没有任何还原路径**。这是需求 8 要解的核心矛盾。

## 二、主流做法盘点（Android 生态）

| 机制 | 是什么 | 关键约束 | 对 Healix 的适配 |
|---|---|---|---|
| **Auto Backup for Apps** | targetSdk ≥ 23 自动参与；云备份到 Google Drive，上限约 **25MB** | Android 12(API 31) 起 `allowBackup`/`fullBackupContent` **已废弃**，改用 `dataExtractionRules`；targetSdk 31+ 时部分厂商机型**即使 `allowBackup=false` 也不一定关闭 D2D 传输** `[A/B]` | ❌ 健康数据静默上传云端，违背隐私定位 |
| **`adb backup`** | `adb backup` 导出 `.ab`（TAR/AES） | **自 Android 12 起废弃**；且 `allowBackup=false` 的应用**被自动排除** `[A]` | ❌ 已废弃 + 本应用主动排除 |
| **应用内 JSON 导出/导入** | App 自己序列化，用户选路径（SAF） | 无权限、跨设备、可审阅 | ✅ 与本地优先定位一致 |
| **DB 文件快照** | 直接拷贝 `healix.db` | 需处理 `-wal`/`-shm`；跨 schema 版本不安全；普通用户不可操作；无 root 难以取回 | ❌ 脆弱、不可操作 |
| **DataStore** | 键值/Proto 存储 | Healix 设置已在 Room（`settings` 表），不适用 | ❌ 不适用 |
| **SAF 目录双向同步** | 持续把导出写到用户选定目录 | 单用户场景过重；持续同步带来复杂度与隐私面 | ❌ 过度设计 |
| **Health Connect / Google Fit 只读同步** | 与系统/穿戴数据互通 | 本应用不采集传感器数据（战略分工） | ⚪ 未来观察项，非本期 |

`[A]` = Android 官方文档；`[B]` = 厂商/安全资料。参考：Android 官方 "Back up user data with Auto Backup"、OWASP MASTG Backups、Lint `DataExtractionRules`。

## 三、推荐方案详细设计

### 3.1 双向 JSON（核心）

**导出（沿用并加固）**
- 保留 `ExportWriter.buildJson` 结构（含 `format`/`version` 头，`ExportWriter.kt:27,34-37`）。
- 把当前 DB 的 schema 版本写入导出头（如 `schema_version: 3`），供导入时判断兼容性。
- 导出文件为**明文 JSON** → UI 上必须明确提示"含健康数据，请妥善保管"。

**导入（新增 `ImportReader`）**
- 入口：「我的」页数据组，与「导出备份」并列新增「导入数据」（`view_item` 复用 `row_setting_value` 风格）。
- 载体：SAF `ACTION_OPEN_DOCUMENT`（`type=application/json`），**不申请存储权限**（与导出一致）。
- 解析与写入规则：
  - `events`：按 `client_event_id` UNIQUE 去重（`db/EventEntity.kt:17`），`INSERT OR IGNORE` 语义 → **幂等**，重复导入不产生重复行。
  - `presets` / `daily_plans` / `daily_reviews` / `goals` / `reminders` / `training_plans` / `knowledge_*`：按主键 upsert，保留现有数据（**合并**，不覆盖）。
  - `settings`：只写**非敏感**键；API Key 不在其中（本就不导出）。
  - 结果反馈：Toast/内联文案报告"导入 N 条，跳过 M 条（已存在）"，失败给明确原因（格式不符 / 版本不兼容）。
- **API Key 处理**：导入**不含** key → 提示用户到设置页重新填写（这是刻意的隐私取舍，绝不把明文 key 放进可搬运文件）。

### 3.2 迁移安全网

1. **预迁移 DB 快照**：在 `AppDatabase.get()` 之前（`HealixApp.onCreate` 阶段），读取当前 DB 的 `PRAGMA user_version` 与代码 `version=3` 比对；发现"将升级"时，先把 `healix.db` / `-wal` / `-shm` 复制到 `filesDir/snapshot/` 并保留最近 1–2 份。
   - 目的：万一某个 Migration 在真机上抛错（当前策略是崩溃而非静默删库，`AppDatabase.kt:143-145`），用户至少有一份升级前快照可人工恢复。
2. **提交 schema JSON**：补齐 `app/schemas/com.healix.app.db.AppDatabase/3.json`，并在 CI 增加检查——**当前版本的 schema JSON 必须存在于仓库**（现在缺 `3.json`，迁移无法被校验）。
3. **迁移测试**：引入 `androidx.room:room-testing`（**已是测试期依赖**，`app/build.gradle` androidTest）写 `MigrationTestHelper` 用例，覆盖 v1→v3、v2→v3。CI 有 Android SDK，可跑 androidTest。
4. **禁止破坏性迁移**：保持不变（`AppDatabase.kt:143-145`）。

### 3.3 隐私

- `allowBackup=false` + `fullBackupContent=false` + `dataExtractionRules` 全排除（cloud-backup + device-transfer）**保持不变**。
- API Key 只存 `EncryptedSharedPreferences`（`SecretStore.kt`），不导出、不写入任何备份。
- 导出文件为明文 → UI 明示；如需更强保护，P2 可加"导出时用口令加密"（本期不做，避免引入密钥管理复杂度）。
- 建议核对导出 `settings` 是否包含用户自述类自由文本（`GOAL_STATEMENT`、`profile_*`）；这些是用户自己的数据，**保留导出**，但提示语要覆盖"包含你的个人描述"。

### 3.4 跨设备 / 重装恢复路径（动作序列）

1. 旧机：「我的」→「导出备份」→ 选保存位置 → 得到 `healix-backup-YYYY-MM-DD.json`。
2. 用户把该文件放到任一可搬运介质（云盘 / 电脑 / 微信文件传输）。
3. 新机：安装 Healix → 「我的」→「导入数据」→ 选该文件 → 提示"导入 N 条，跳过 M 条"。
4. 用户到设置页重新填 API Key（导入不含 key）。
5. 目标设定：若导入数据含 `goals`，则首次引导（PRD 需求 5 的 `GOAL_SETUP_DONE`）按导入结果决定是否跳过。

### 3.5 用户可操作性

- 全程 SAF，无需存储权限；导出/导入都是"点一次 + 选文件"。
- 导入结果必须可见（条数 + 跳过原因），不做静默失败。
- 版本不兼容时给出明确提示（如"该备份来自更新的版本，请升级 App 后再导入"）。

## 四、其它方案为何不选（逐条否决）

| 方案 | 否决理由 |
|---|---|
| **Auto Backup 打开** | ① 健康数据静默上传 Google Drive，直接违背"只存本地是隐私优势"的定位；② 25MB 上限对长期记录有溢出风险；③ targetSdk 31+ 下部分厂商机型 `allowBackup=false` 也不保证关闭 D2D，**控制力不足**。 |
| **`adb backup`** | Android 12 起废弃；且 `allowBackup=false` 会使其自动排除；普通用户无法操作。 |
| **DB 文件快照作为主方案** | 需处理 WAL/SHM、跨 schema 不安全、无 root 难取回、用户完全不可操作。仅**降级为内部安全网**（见 3.2）。 |
| **DataStore** | 设置已在 Room `settings` 表；引入第二套存储违反"唯一事实来源"纪律。 |
| **SAF 目录持续同步** | 单用户、低频迁移场景，持续同步收益低、复杂度与隐私面高。 |
| **只导出不导入** | 等于没有迁移能力（当前状态），不解决需求 8。 |

## 五、现存缺口清单（必须点名）

| # | 缺口 | 影响 | 建议动作 |
|---|---|---|---|
| 1 | **无导入** | 导出的 JSON 是"死数据"，换机/重装无法还原 | 本期新增 `ImportReader`（P0） |
| 2 | **`allowBackup=false` + dataExtractionRules 全排除** | 默认零系统级恢复路径（设计使然，但需有替代） | 由应用内迁移包承接（P0） |
| 3 | **`3.json` schema 缺失**（DB version=3） | 迁移无法被 CI 校验，升级风险不可控 | 补齐 + CI 检查（P0） |
| 4 | **无预迁移快照** | 迁移若在真机抛错，用户无退路 | 升级前自动快照（P1） |
| 5 | **无迁移测试** | 升级正确性无自动验证 | 加 `MigrationTestHelper`（P1） |
| 6 | **导出为明文** | 健康数据落盘可被读取 | UI 明示；加密列 P2 |
| 7 | **导出 settings 含用户自述文本** | 隐私知情 | 提示语覆盖；保留导出 |
