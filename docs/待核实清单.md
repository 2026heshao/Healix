# Healix 待核实清单

本文件汇总 Android 侧代码中所有 `[待核实: ...]` 占位项。
**每一项在核实并替换之前，对应的功能都不算完成。**

原则（C1 反幻觉）：不确定的平台地址、模型名、版本号、ROM 行为，一律写占位符，
不凭记忆硬编码。核实方式写在每一项后面。

生成日期：2026-10-03
维护者：android-builder

## 四、功能完整度（非阻塞，但影响可用性）

| # | 待核实项 | 出现位置 | 说明 |
|---|---|---|---|
| 14 | 「今日无记录且已过 20:00」的判定是否需要考虑日界线（当前固定用 4:00） | `notify/QuickInputService.refreshNudgeSubtitle()` / `DEFAULT_DAY_START_HOUR` | 当前硬编码 4 小时日界线。若用户在设置页改了日界线，通知文案的判定应与之一致 —— 需改为读 settings 表。**MVP 阶段接受这个不一致** |
| 15 | 多事件拆分后的"撤销"语义 | `repo/EventRepository.undo()` | 当前只软删除首条，兄弟条（各自独立 clientEventId）无法从首条反查。若用户认为"撤销应删整批"，需在 events 表加 `batch_id` 列（**会触发 Room version 升级 + Migration**，不可轻率） |
| 16 | `toInt` / `toDouble` 的舍入在 `.5` 平局时与 Python 不一致 | `parse/SchemaValidator.kt` 的 `Math.round` / `roundTo2` | Python `round()` 是**银行家舍入**（round-half-even，`round(300.5)=300`），Kotlin `Math.round` 是**半上舍入**（`Math.round(300.5)=301`）。契约测试的 67 条断言未覆盖 `.5` 平局（实测 `to_int(300.7)`→301 两边一致），因此**当前不构成漂移**。但若将来模型输出大量 `X.5` 值，需改为复刻 Python 的 `round()` 语义。**MVP 接受此差异**，已在代码注释中标注 |
