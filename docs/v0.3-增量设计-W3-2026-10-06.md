## 1. 实现方案

### 1.1 批次 B2 — 需求2 记录页合并滚动区

#### 1.1.1 目标与现状
现状（`fragment_record.xml`，594 行，外层 `LinearLayout` 竖直）自上而下：
`[顶栏 56dp] [divider] [goalArea ≈142dp] [presetScroll 48dp] [presetDivider] [statusRow 48dp] [nudgeBar 48dp] [planBar 48dp] [offlineBar ~32dp] [undoBar 48dp] [FrameLayout(list 权重1 + emptyState)] [inputBar 64dp]`。

**关键事实**：`goalArea` 到 `offlineBar`/`undoBar` 这一整块**恒不滚动**（只在 `list` 上方固定）。上游 §2（`:95`）量化：约 **300–350dp 恒不滚动**（≈屏高 35–40%）→ 手指落在目标卡片/状态行上滑动时页面不动 = "分区割裂感"。

目标：**顶部内容型信息随滚动离场**；**操作反馈（状态提示/撤销条）与输入条保持固定**。

#### 1.1.2 目标结构（`fragment_record.xml` 重构）— **BP-2 收窄后的 header 范围**
```
LinearLayout(recordRoot, vertical)
├─ RelativeLayout  [顶栏：dateLabel + btnSettings]        ← 固定（不变）
├─ View            [divider]                              ← 固定（不变）
├─ TextView(offlineBar)  「状态提示条」                    ← 固定（操作反馈；默认 gone）
├─ LinearLayout(undoBar) 「撤销条」                        ← 固定（操作反馈；默认 gone）
├─ RecyclerView(list)  weight=1                           ← 唯一滚动轴
│     adapter = ConcatAdapter(headerAdapter, eventAdapter, emptyAdapter)
│     clipToPadding=false, paddingBottom=@dimen/list_bottom_pad(80dp)   （不变）
└─ LinearLayout(inputBar)  [input/spinner/stateLabel/btnSend]  ← 固定（不变）
```
- **header（随内容滚动）** —— 由 `item_record_header.xml` 承载，含以下 6 段：
  `goalArea`（主目标行 + 三卡 + 盈余行）+ `presetScroll` + `presetDivider` + `statusRow`（多维状态行）+ `nudgeBar`（监督提示条）+ `planBar`（计划提示条）。
- **固定区（不进滚动区）** —— 顶栏 + divider + `offlineBar`（状态提示条）+ `undoBar`（撤销条）+ `inputBar`。

> ⚠️ 术语对齐：BP-2 所称「`statusBar`(状态提示)」= 本仓 `fragment_record.xml:441-455` 的 **`offlineBar`**（注释 `:435-440` 自述"状态提示条"）；所称「`statusRow`」= `:377-407` 多维状态行（`运动 2/3 · 睡眠…`，**内容型 → 进 header**）。两者不同，勿混。

**固定区量化（对照上游「300–350dp 死区」目标）**：
| 场景 | 固定区构成 | 高度 |
|---|---|---|
| 常驻（联机、未配置-off） | 顶栏 56dp + divider 1dp（`offlineBar`/`undoBar` 默认 `gone`） | **≈57dp** |
| 最坏（离线条 + 撤销条同显） | 57 + `offlineBar`(~32dp) + `undoBar`(48dp) | **≈137dp** |
> 结论：B2 后固定区 **常驻 ≈57dp / 最坏 ≈137dp**，**远低于 300–350dp** → **达标**（上游 §2 目标）。

#### 1.1.3 ConcatAdapter 组成与 ViewType 划分
| 段 | 适配器 | 条目数 | 备注 |
|---|---|---|---|
| 0 | **`RecordHeaderAdapter`（新）** | **恒 1** | 承载 `item_record_header.xml` |
| 1 | **`EventAdapter`（BP-3：零改动）** | N（事件数） | 现有实现原样（ConcatAdapter 直接包裹） |
| 2 | **`RecordEmptyAdapter`（新，BP-1）** | `isEmpty ? 1 : 0` | 承载 `item_record_empty.xml`（复刻原 `emptyState`） |

新文件 `ui/RecordListAdapters.kt` 含两个小适配器：
```kotlin
internal class RecordHeaderAdapter(
    private val onHeaderBound: (ItemRecordHeaderBinding) -> Unit,   // 首次绑定时回传，供 Fragment 记引用
) : RecyclerView.Adapter<RecordHeaderAdapter.VH>() {
    override fun getItemCount() = 1
    override fun onCreateViewHolder(p: ViewGroup, v: Int) =
        VH(ItemRecordHeaderBinding.inflate(LayoutInflater.from(p.context), p, false).also(onHeaderBound))
    override fun onBindViewHolder(h: VH, position: Int) = Unit      // header 内容由 Fragment 渲染
    class VH(val b: ItemRecordHeaderBinding) : RecyclerView.ViewHolder(b.root)
}

internal class RecordEmptyAdapter : RecyclerView.Adapter<RecordEmptyAdapter.VH>() {
    private var empty = true
    fun setEmpty(v: Boolean) { if (v == empty) return; empty = v; notifyDataSetChanged() }
    override fun getItemCount() = if (empty) 1 else 0
    override fun onCreateViewHolder(p: ViewGroup, v: Int) =
        VH(ItemRecordEmptyBinding.inflate(LayoutInflater.from(p.context), p, false))
    override fun onBindViewHolder(h: VH, position: Int) = Unit
    class VH(val b: ItemRecordEmptyBinding) : RecyclerView.ViewHolder(b.root)
}
```
- **ViewType 不冲突**：`EventAdapter` 的两个方法都忽略 `viewType`；`ConcatAdapter` 内部按"适配器序号 + 子位置"分派，三段各自 0 基。
- **空态驱动**：现 `observe()` 里 `binding.emptyState.visibility = …`（`:358-360`）改为 `emptyAdapter.setEmpty(list.isEmpty())`。

- **⚠️ 时序关键点（首帧补渲染）**：`observe()` 在 `onViewCreated`（`:204`）启动，flows 可能**先于** header 被绑定到达（RecyclerView 首次 layout 在 `onViewCreated` 返回之后）。故 Fragment 必须：
  1. header 绑定前，`renderGoalArea()` / `renderPresetStrip()` 因 `headerBinding == null` **直接 return**（沿用现有 `if (_binding == null) return` 范式）；
  2. `onHeaderBound` 回调里保存引用 **并各调一次** `renderGoalArea()` / `renderPresetStrip()` / 刷新 header 内的 `statusRow` / `nudgeBar` / `planBar`（"补渲染"），否则首帧 header 空白。
  > 补渲染必须**幂等**（现有 render 已幂等，`:516` 注释）且**纯本地、0 AI**。

#### 1.1.4 三处迁移点的**具体改法**

**迁移点① — `SwipeController` / `addOnItemTouchListener`（纠偏 C2，实为零改动）**
- `binding.list.addOnItemTouchListener{...}`（`:172-180`）**保留不动**（`binding.list` 仍是 RecyclerView）→ 覆盖 **header 内**按下（`findChildViewUnder` 命中 header）与事件行按下。
- `binding.root.setOnTouchListener{ swipe.closeIfOutside(null) }`（`:183-186`）**保留** → 覆盖 **RecyclerView 之外**的固定区（顶栏 / `offlineBar` / `undoBar` / `inputBar`）。
- `EventAdapter` 每行 `swipeItem.setOnTouchListener{ swipe.onTouch(...) }`（`:804-813`）**保留不动**。
- 回归验证：滑开一行 → 按 header 目标区 → 行回弹（走 list 的监听器）。

**迁移点② — `InputBarHeightAnimator` 的 `smoothScrollToPosition`（纠偏 C3）**
```kotlin
// RecordFragment.onViewCreated（现 :199-202）
InputBarHeightAnimator.bind(binding.input, binding.inputBar) {
    val eventsLast = eventAdapter.itemCount - 1                // EventAdapter 坐标：最后一个事件的子位置
    if (eventsLast >= 0) {
        binding.list.smoothScrollToPosition(eventsLast + HEADER_ITEM_COUNT)   // 转根坐标（header 恒 1）
    }
}
```
- 常量 `private const val HEADER_ITEM_COUNT = 1`（`RecordFragment` companion）。`eventAdapter` 零改动。
- **末行分隔线不动**：`EventAdapter.VH.bind` 的 `bindingAdapterPosition == items.size - 1`（`:884`）在 **EventAdapter 自身坐标**内判定，ConcatAdapter 不改变它（纠偏 C3）。

**迁移点③ — `emptyState` → ConcatAdapter footer（BP-1 裁定）**
- 删除 `FrameLayout` + `emptyState` 覆盖层；`list` 直接作 `recordRoot` 的 `weight=1` 子视图。
- 把原 `emptyState`（`fragment_record.xml:509-530`：`empty_hint` + `empty_example`，居中）**原样抽出**为 `item_record_empty.xml`（**单一事实来源，避免两套观感**）。
- 空态显示由 `emptyAdapter.setEmpty(list.isEmpty())` 驱动（替换原 `:358-360`）。
- **视觉细节**：footer 条目在 header 之下（`layout_height=wrap_content` + 适度纵向 padding），不再"整块垂直居中"。→ 见 §7 **BP-1b-1**（保留项，非阻塞）。

#### 1.1.5 header 渲染目标
`renderGoalArea()` / `renderGapRow()` / `renderCards()` / `renderPrimaryRow()` / `renderPresetStrip()` 全部改为**写入 `headerBinding`**；`observe()` 内对 header 视图的写入（`statusRow` / `nudgeBar` / `planBar`）同样重定向到 `headerBinding`（并加 `headerBinding ?: return@launch` 守卫）。**不动** `inputBar` 内视图（`spinner`/`stateLabel`/`input`/`btnSend`）与固定区（`offlineBar`/`undoBar`）。

#### 1.1.6 固定区与 `undoBar` 处置（BP-2）
- `undoBar` 与 `offlineBar` **抽出为 `recordRoot` 的固定子视图**，位于 **顶栏 divider 之后 / RecyclerView 之前**。
- 语义：二者是**操作反馈**（撤销条 / 离线·未配置提示），常驻可见比随滚离场更合理；且 `UndoBar` 的 `WeakHashMap<View,Runnable>` 定时器**绝不能**挂在会被回收的 View 上。
- `UndoBar.bind(container=binding.undoBar, leftText=binding.undoLeft, action=binding.undoAction, …)`（`:319-326`、`:464-471`）**不变**（`undoBar` id 仍在 `fragment_record.xml` 顶层）。
- 视觉变化：`offlineBar`/`undoBar` 由"bars 之下"上移到"工具栏之下"（仍在 list **之上**）→ 与设置页 `undoBar` 位置一致（`fragment_settings.xml:46-50`）。

#### 1.1.7 与他会话 WIP 的重叠度结论（纠偏 C9/C10）——**核心交付**
**语义**：WIP 4 hunk = **"目标自定义文本"特性**（`GOAL_MODE_CUSTOM` + `HomeGoal.statement` 展示 + `GoalSetupSheet`/`completeGoalSetup` 三参）= **行为改动**；B2 = **视图搬迁**（`binding.goal*` → `headerBinding.goal*`）= **结构调整**。二者**语义正交**。

**逐 hunk 重叠判定**（对 B2 的编辑面）：
| WIP hunk | 位置 | B2 是否编辑同一方法/区域 | 判定 |
|---|---|---|---|
| H1 `openGoalEditor` | `:271-280` | 否（B2 不碰 `GoalSetupSheet` 调用） | **不重叠** |
| H2 `renderPrimaryRow` 调用点 | `:552-556`（改 `:554`） | **是**（B2 需改 `:555/:558/:565/:575/:578-579/:583/:586-589` 的 `binding.goal*`→`headerBinding.goal*`） | **重叠（同方法、行相邻）** |

| H4 `maybeShowGoalSetup` | `:683-689` | 否 | **不重叠** |

**结论**：
1. **真实文本重叠 = 1 个方法（`renderPrimaryRow`），且行级不相交**（WIP 改 `:554` 的调用，B2 改 `:555+` 的 view 引用）→ **人工合并极易**。

## 6. 共享知识（跨文件约定）

1. **keep-alive 保活范式**：二级页 `hide/show` 复用，`onResume` **不触发**；刷新只认 `onHiddenChanged(false)`（`NavHost.kt:74-80`）。B2 不涉二级页，但 7.1/7.4 的否决论据依赖此事实（C6）。
2. **`undoBar` 不变量**：`UndoBar` 用 `WeakHashMap<View,Runnable>` 持 5s 定时器（`UndoBar.kt:36-37`）→ 宿主须是**非回收的固定 View**。**任何进 RecyclerView 的视图都不得做它的容器**（BP-2）。
3. **header 范围（BP-2）**：滚动区 = 内容型（`goalArea`/`presetScroll`/`presetDivider`/`statusRow`/`nudgeBar`/`planBar`）；固定区 = 操作型（顶栏/`offlineBar`/`undoBar`/`inputBar`）。二者**不得互串**。
4. **Adapter 坐标双空间**：`bindingAdapterPosition`（子适配器坐标，`:884` 末行分隔线用）与根坐标（`smoothScrollToPosition` 用）**不是一回事**；ConcatAdapter 下前者不变、后者需 `+HEADER_ITEM_COUNT`。
5. **viewBinding ↔ 静态检查**：`check_view_binding`（`check_kotlin.py:332-379`）要求 `binding.xxx` 能在本文件 inflate 过的布局里找到 `@+id`；`BINDING_RE` 只认字面量标识符 `binding`（`:323`）→ 命名为 `headerBinding.` 的引用该检查器不覆盖（但 **viewBinding 编译期**兜住"id 不存在"）。类型参数 `: ItemRecordHeaderBinding` 会被登记为 used layout（`:361-368`）。
6. **`check_references`**（`check_resources.py:94-140`）：布局 `@dimen/@color/@style/@string/@drawable` 与 Kotlin `R.string/color/dimen/layout/drawable/array` 必须存在。
7. **无本机 JDK / 设备，CI 唯一编译验证**；真机项见 §9。
8. **WIP 领地（只读）**：`GoalSetupSheet.kt`、`MainViewModel.kt`、`PlanChangeWriter.kt`、`sheet_goal_setup.xml`、`RecordFragment.kt` 的 4 个 hunk —— B2 **不得回退**其语义（见红线）。
