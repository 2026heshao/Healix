取舍

决定不做什么，比决定做什么难。

这个项目里每一行代码都对应一次拒绝。下面八条是拒绝得最狠的，也是它能用起来的原因。

没有做 做成了这样 · 为什么
拍照识别热量
先落库，再识别 拍照要先识别成功才能落库，识别失败时你什么都没留下。原话先存下来，抽错还能改。
Agent 自主决策
Prompt Chaining 两级链路 抽取链与计划链各有确定的输入输出，可以用 22 条用例离线回归。多步自主决策没法这样验收。
云端账号
只存本机 SQLite 没有账号，就不存在「谁看过你的数据」这个问题。代价是换机要手动导出 JSON。
后台定时复盘
打开应用时触发，加一个手动按钮 国行 ROM 会杀后台，定时任务在实际机型上不生效。与其做一个看起来有、实际不跑的开关，不如让你按一下。
圆角卡片与阴影
留白加 1dp 细线分区 层级只由字号、字重、灰度决定。圆角花样和阴影是廉价感的主要来源，去掉之后界面才安静。
多色强调
全局只有一个强调色 一屏里出现两个强调色，就等于没有东西是强调的。语义色只在真实状态和文字上出现，绝不铺面。
纯 AI 输出直接进库
raw_text 必落库 抽错时唯一的后悔药是那句原话，不是模型重试的结果。改原话，一次就稳。
二十个功能都做一半
饮食、运动、增重计划、生病记录四件事做到能用 四条线各自闭环，比二十条线各自半成品有价值。没做完的功能就写在进度里，不假装有。
隐私

你的数据不出手机，除了那一次请求。

需要联网的只有一次模型调用，发出去的是你刚写的那句话。其余全部在本机完成。

密钥

API key 加密存本机

走 EncryptedSharedPreferences，绝不进代码、仓库、日志与 SQLite 表。

原文

原话必落库

raw_text 是每条记录的一部分。抽错时改的是它，不是模型的重试。

接口

服务商随时可换

baseUrl 与模型名只存在设置页，代码里只有占位符。换一家不用改代码。

文档

PDF 解析在本机

知识库的解析在手机上完成，原文件不出设备。只有被引用的片段会进对话。

代价说清楚：数据只在这台手机上，卸载或清除应用数据就会丢。所以「导出备份」不是一个可选项，它是这件事的必要配套。
